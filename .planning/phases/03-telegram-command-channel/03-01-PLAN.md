Create `src/hitl/approval-queue.ts`:
- Uses better-sqlite3 (already installed) with a dedicated `approvals` table in `~/.openclaw/data/approvals.db`.
- `initApprovalDB(dbPath?: string): Database` -- creates table if not exists: `id TEXT PRIMARY KEY, action TEXT, params TEXT, source TEXT, status TEXT DEFAULT 'pending', created_at TEXT, resolved_at TEXT, telegram_message_id INTEGER`.
- `savePendingApproval(approval: ApprovalRequest, dbPath?: string): void` -- INSERT into approvals table. Params stored as JSON string.
- `getPendingApproval(id: string, dbPath?: string): ApprovalRequest | null` -- SELECT by ID, parse params JSON.
- `updateApprovalStatus(id: string, status: ApprovalStatus, dbPath?: string): boolean` -- UPDATE with `WHERE status = 'pending'` for atomic claim. Return true if row updated, false if already processed (race condition protection per research Pitfall 5).
- `getPendingCount(dbPath?: string): number` -- COUNT WHERE status = 'pending'.
- `requestApproval(request: ActionRequest, bot: Bot, operatorChatId: number, dbPath?: string): Promise<string>` -- generates UUID, saves to DB, builds InlineKeyboard with `Approve` (`approve:{id}`) and `Reject` (`reject:{id}`) buttons, sends message via `bot.api.sendMessage()` with `formatApprovalMessage()` and MarkdownV2 parse mode, stores telegram_message_id in DB, returns approvalId.
- All functions log to stderr as structured JSON with `component: "approval-queue"`.

Create `src/telegram/callbacks.ts`:
- `registerCallbacks(bot: Bot)` -- registers:
  - `bot.callbackQuery(/^(approve|reject):(.+)$/, handler)` -- extracts decision and approvalId from regex match. Calls `getPendingApproval()` to check it exists and is pending. If already processed, replies "Already processed" via `ctx.answerCallbackQuery()`. If pending:
    - On approve: call `updateApprovalStatus(id, 'approved')`, edit message text to show "Approved and executed", call `ctx.answerCallbackQuery()`.
    - On reject: call `updateApprovalStatus(id, 'rejected')`, edit message text to show "Rejected and discarded", call `ctx.answerCallbackQuery()`.
  - Note: actual action execution on approve is NOT implemented here -- that will be wired when skills exist. For now, approval just updates status. The action execution callback can be registered separately.
- Use `ctx.editMessageText()` to update the original approval message (removes buttons, shows result).

Modify `src/hitl/enforce.ts`:
- The `enforceHITL` function currently blocks YELLOW-tier actions with `reason: 'blocked (approval channel not yet available)'`.
- Change it to return `{ allowed: false, tier: 'YELLOW', reason: 'YELLOW tier: queued for Telegram approval', logged: true, approvalId: undefined }` for YELLOW-tier actions.
- Add a new exported function: `enforceHITLAsync(request: ActionRequest, config: TierConfig, bot: Bot, operatorChatId: number, dbPath?: string): Promise<HITLResult>` -- same as `enforceHITL` but for YELLOW tier it calls `requestApproval()` from approval-queue and returns the result with `approvalId` set.
- Keep the synchronous `enforceHITL` working for backward compatibility (GREEN auto-approves, RED blocks, YELLOW returns queued status).
- RED tier remains always blocked -- no approval path, no change to RED handling.
