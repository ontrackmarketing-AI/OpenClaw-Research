Install googleapis: `cd ~/.openclaw && npm install googleapis`

Create `src/gmail/types.ts`:
- `GmailConfig` interface: `{ credentialsPath: string; tokenPath: string; pollingIntervalMinutes: number; maxResults: number; }`
- `EmailMessage` interface: `{ messageId: string; from: string; subject: string; date: string; snippet: string; }`
- `TriageCategory` type: `'actionable' | 'informational' | 'spam' | 'calendar-event'`
- `SuggestedAction` type: `'reply' | 'archive' | 'forward' | 'add-calendar' | 'ignore'`
- `TriageResult` interface: `{ messageId: string; from: string; subject: string; date: string; category: TriageCategory; suggestedAction: SuggestedAction; reason: string; calendarEvent?: ExtractedCalendarEvent; }`
- `TriageSummary` interface: `{ results: TriageResult[]; timestamp: Date; totalScanned: number; }`

Create `src/calendar/types.ts`:
- `ExtractedCalendarEvent` interface: `{ title: string; date: string; startTime: string; endTime?: string; duration?: string; location?: string; description?: string; sourceEmailId: string; }`

Create `src/gmail/client.ts`:
- `getOAuth2Client(credentialsPath?: string, tokenPath?: string): OAuth2Client` -- reads Google credentials JSON from `~/.openclaw/config/google-credentials.json` (default), loads saved tokens from `~/.openclaw/config/google-tokens.json` (default), sets up auto-save on token refresh via `oauth2Client.on('tokens', ...)`. NOTE: This is a deliberate exception to SECR-01 (n8n proxy pattern) -- Gmail OAuth2 token refresh is tightly coupled to the googleapis client and cannot be meaningfully proxied through n8n. Document this in the module header.
- `createGmailClient(auth?: OAuth2Client): gmail_v1.Gmail` -- creates `google.gmail({ version: 'v1', auth })`.
- Scopes: `['https://www.googleapis.com/auth/gmail.readonly', 'https://www.googleapis.com/auth/calendar.events', 'https://www.googleapis.com/auth/calendar.readonly']`
- Follow structured JSON logging pattern to stderr with `component: "gmail-client"`.

Create `src/gmail/auth-setup.ts`:
- `runAuthSetup(credentialsPath?: string, tokenPath?: string): Promise<void>` -- one-time interactive OAuth2 flow. Generates auth URL, prints it to console for user to visit, reads authorization code from stdin, exchanges for tokens, saves to token file. This is a standalone script run once during setup.
- Usage: `npx tsx src/gmail/auth-setup.ts`

Create `src/calendar/extractor.ts`:
- `extractCalendarEvent(email: EmailMessage, sessionId: string): Promise<ExtractedCalendarEvent | null>` -- uses `routeAndCall()` from the model router with task type `'calendar-extraction'` (routes to Haiku tier). Prompt instructs the LLM to extract { title, date, startTime, endTime, duration, location } as JSON from the email subject + snippet. If extraction fails or no event detected, return null. Parse the LLM response as JSON with try/catch -- on parse failure, log warning and return null (do not crash the triage pipeline).
- System prompt: "You are a calendar event extractor. Given an email, extract calendar event details as JSON. If no calendar event is present, respond with null. Output ONLY valid JSON, no other text."

Create `src/gmail/triage.ts`:
- `classifyEmail(email: EmailMessage, sessionId: string): Promise<{ category: TriageCategory; suggestedAction: SuggestedAction; reason: string }>` -- uses `routeAndCall()` with task type `'email-triage'` (routes to Haiku tier). Prompt: "Classify this email. From: {from}, Subject: {subject}, Snippet: {snippet}. Respond with JSON: { category: 'actionable'|'informational'|'spam'|'calendar-event', suggestedAction: 'reply'|'archive'|'forward'|'add-calendar'|'ignore', reason: 'brief explanation' }". Parse response as JSON with error handling.
- `triageInbox(auth: OAuth2Client, sessionId: string): Promise<TriageSummary>` -- uses `gmail.users.messages.list()` with query `'is:unread in:inbox'` and `maxResults: 50`. For each message, calls `gmail.users.messages.get()` with `format: 'metadata'` and `metadataHeaders: ['From', 'Subject', 'Date']` (use metadata format to respect Gmail rate limits per research Pitfall 6). Classifies each email. For 'calendar-event' category, also calls `extractCalendarEvent()`. Returns TriageSummary. Rate-limits to sequential processing (single user, 10-50 emails max).
- `formatTriageSummary(summary: TriageSummary): string` -- formats results as MarkdownV2 for Telegram. Groups by category. Each entry shows: numbered item, bold sender, subject, italic suggested action. Uses `escapeMarkdownV2()` from telegram formatters. Include total count header.

- Test `getOAuth2Client` throws helpful error when credentials file is missing.

Create `src/gmail/poller.ts`:
- `startEmailPoller(bot: Bot, operatorChatId: number, auth: OAuth2Client, intervalMinutes?: number): void` -- uses `node-cron` (already installed) to schedule `triageInbox()` at the configured interval. Default: daily at 08:00 (`'0 8 * * *'`). On triage completion, sends formatted summary to operator via `bot.api.sendMessage()` with MarkdownV2 parse mode. For calendar-event results, includes inline buttons: "Add to Calendar" (`cal:add:{messageId}`) and "Skip" (`cal:skip:{messageId}`). Stores the historyId from the last triage in a JSON file at `~/.openclaw/data/gmail-state.json` for deduplication.
- `triggerTriage(bot: Bot, operatorChatId: number, auth: OAuth2Client): Promise<void>` -- runs triage immediately (on-demand). Same logic as the scheduled triage but triggered manually. Sends "Scanning inbox..." first, then the results.
- `getLastHistoryId(statePath?: string): string | null` -- read from gmail-state.json.
- `saveLastHistoryId(historyId: string, statePath?: string): void` -- write to gmail-state.json.
- Use historyId-based polling: After first full scan, subsequent polls use `gmail.users.history.list()` with `startHistoryId` to fetch only new messages. If history.list fails (e.g., historyId expired), fall back to full inbox scan.
- Follow structured JSON logging pattern to stderr with `component: "gmail-poller"`.

- Add `/triage` command handler: calls `triggerTriage()` with the bot instance, operator chat ID, and Gmail auth client. Sends "Scanning inbox..." immediately, then the full triage summary on completion.
- The Gmail auth client should be lazily initialized on first /triage call using `getOAuth2Client()`. If credentials are not configured, reply with a helpful error message telling the operator to run the auth setup.
- Add `/quiet` command handler (stub for quiet hours): replies with current quiet hours config and a note that configuration is via environment variables. Quiet hours are checked before sending any non-urgent Telegram message (this lays groundwork for COMM-07 in 03-03).
