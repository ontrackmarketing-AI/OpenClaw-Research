**Create `src/proposals/industry-context.ts`** -- Industry context retrieval for PROP-06:

- Import `hybridSearch` from `../memory/hybrid-search.js`
- This module provides the "client knowledge RAG" referenced in PROP-06. Since Phase 6 (Per-Task RAG) hasn't been built yet, this uses Phase 2's hybrid search (FTS5 + Qdrant) on the existing memory system as a substitute. When Phase 6 delivers per-task RAG collections, this module is the single swap point.

- Export `async searchIndustryContext(industry: string, keywords: string[]): Promise<string>`:
  - Build search query: `${industry} marketing pain points ${keywords.join(' ')}`
  - Call `hybridSearch(query, { limit: 5 })` to get top 5 results
  - Concatenate result content strings, separated by `\n\n---\n\n`
  - If no results found, return a minimal fallback string: generic industry pain points for the target verticals (plumbing, solar, dental, legal) hardcoded as a lookup map
  - Log structured JSON to stderr: component='industry-context', action='search', industry, resultCount
  - Return the concatenated context string

- Export `getIndustryPainPoints(industry: string): string[]`:
  - Synchronous helper that returns hardcoded pain points for known industries:
    - plumbing: ["No website or outdated website", "Zero Google reviews", "Competitors running Google Ads", "No Google Business Profile", "Word-of-mouth only"]
    - solar: ["High customer acquisition cost", "Complex sales cycle", "Regulatory compliance messaging", "Competitor price undercutting", "Low online visibility"]
    - dental: ["Patient retention and recall", "Competing with corporate dental chains", "Insurance vs cash-pay messaging", "Negative review management", "New patient acquisition cost"]
    - legal: ["Bar advertising restrictions", "High PPC cost ($50-100/click)", "Reputation management", "Practice area differentiation", "Client trust building"]
  - Default (unknown industry): ["Low online visibility", "No digital marketing strategy", "Competitor threat", "Lead generation challenges", "Brand awareness gap"]
  - This provides a safety net when the memory system doesn't have relevant content yet

**Create `src/proposals/crm-trigger.ts`** -- GHL qualified-stage handler:

- Import `runProposalPipeline` from `./pipeline.js`
- Import `ProposalPipelineOptions` from `./types.js`
- Import `getProposalByContactId` from `./state.js`
- Import `searchIndustryContext`, `getIndustryPainPoints` from `./industry-context.js`
- Import `assemblePitchDeckContent` from `./assembler.js`
- Import `logAction` from `../notion/action-log.js`
- Import `getBotInstance` from `../telegram/bot.js`

- Define `GHLWebhookEvent` interface matching the GHL OpportunityStageUpdate payload:
  ```typescript
  interface GHLWebhookEvent {
    type: string;
    locationId: string;
    id: string;           // Opportunity ID
    assignedTo: string;
    contactId: string;
    monetaryValue: number;
    name: string;
    pipelineId: string;
    pipelineStageId: string;
    source: string;
    status: string;
    dateAdded: string;
  }
  ```

- Export `async handleQualifiedLead(event: GHLWebhookEvent): Promise<void>`:

  **Step 1: Dedup check**
  - Build idempotency key: `${event.id}:${event.pipelineStageId}:${event.dateAdded}`
  - Check if a proposal already exists for this contact in non-terminal status via `getProposalByContactId(event.contactId)`
  - If found with same trigger source containing the opportunity ID, log skip and return
  - This prevents duplicate pitch decks from webhook retries or pipeline back-and-forth

  **Step 2: Pull contact data**
  - For the initial implementation, extract what's available from the webhook event itself (name from event.name, contactId)
  - Attempt to fetch enriched contact data from GHL via the n8n proxy (Phase 1):
    - POST to `http://localhost:5678/webhook/ghl-contacts-proxy` with `{ action: 'get_contact', contactId: event.contactId }`
    - Parse response for firstName, lastName, companyName, industry, and any custom fields
    - If the proxy call fails (GHL not configured yet), use event.name as company name and 'unknown' for industry
  - Log structured JSON with contact data retrieval result

  **Step 3: Search industry context and assemble content (PROP-06)**
  - Call `searchIndustryContext(contactData.industry, getIndustryPainPoints(contactData.industry))`
  - Call `assemblePitchDeckContent(contactData, industryContext)` to build the pitch deck text
  - The assembled content becomes the `transcriptText` for the pipeline (reused as the analysis input -- the pipeline's analyzer will treat it as pre-structured content)

  **Step 4: Run proposal pipeline (single code path)**
  - Get bot instance via `getBotInstance()`
  - Get operator chat ID from `process.env.TELEGRAM_OPERATOR_ID`
  - Build `ProposalPipelineOptions`: `{ transcriptText: assembledContent, contactId: event.contactId, contactName: \`${contactData.firstName} ${contactData.lastName}\`, company: contactData.companyName, industry: contactData.industry, triggerSource: \`crm-trigger:qualified:${event.id}\`, skipDiscovery: true }`
  - Call `runProposalPipeline(options, \`crm-trigger-${event.id}\`, bot, chatId)`
  - This reuses the full pipeline state machine from Plan 05-01: creates proposal record, runs analysis, skips discovery (skipDiscovery: true), generates Gamma deck, sends Telegram HITL preview -- all through a single code path
  - The pipeline handles proposal record creation, Gamma generation, status updates, and Telegram preview internally

  **Error handling:** Full try/catch wrapper. On failure: log error to stderr with structured JSON, log to Notion as 'error' type, send Telegram notification to operator: "CRM pitch deck failed for {company}: {error.message}". Never throw -- the webhook listener must not crash.

**Create `src/proposals/webhook-listener.ts`** -- HTTP endpoint for n8n-relayed GHL webhooks:

- Import `createServer` from `node:http`
- Import `handleQualifiedLead` from `./crm-trigger.js`
- Import `initProposalDB` from `./state.js`

- Read `GHL_QUALIFIED_STAGE_ID` from process.env -- do NOT hardcode the UUID
- Default port: 8090 (configurable via `PROPOSAL_WEBHOOK_PORT` env var)
- Bind to `127.0.0.1` only (localhost -- Tailscale is the sole remote access path, per Phase 1 convention)

- Export `startWebhookListener(port?: number): http.Server`:
  - Ensure proposal DB is initialized via `initProposalDB()`
  - Create HTTP server handling POST to `/webhook/ghl`:
    - Read request body (accumulate chunks)
    - **Return 200 immediately** before processing (per anti-pattern in research: GHL retries on non-200)
    - Parse JSON body
    - If `event.type === 'OpportunityStageUpdate' && event.pipelineStageId === GHL_QUALIFIED_STAGE_ID`:
      - Call `handleQualifiedLead(event)` -- fire-and-forget (catch errors, log, never crash)
    - All other event types: log to stderr as info and ignore (future expansion)
    - Non-POST or non-/webhook/ghl requests: return 404
  - Listen on `127.0.0.1:${port}`
  - Log structured JSON: component='webhook-listener', action='started', port

- Export `stopWebhookListener(server: http.Server): Promise<void>`:
  - Graceful shutdown: `server.close()` wrapped in a promise
