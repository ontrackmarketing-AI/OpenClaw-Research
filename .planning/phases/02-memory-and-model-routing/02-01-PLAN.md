**Step 1: Create `~/.openclaw/src/memory/fts5-index.ts`** -- SQLite FTS5 full-text search:

- `initFTS5Index(dbPath?)`: Open (or create) SQLite database at `~/.openclaw/memory/index.db`. Enable WAL mode. Create tables:
  - `documents`: id (PK), path (UNIQUE), content_hash, doc_type, updated_at, token_count
  - `chunks`: id (PK), document_id (FK -> documents ON DELETE CASCADE), chunk_index, content, token_count, created_at
  - `chunks_fts USING fts5(content, content='chunks', content_rowid='id', tokenize='porter unicode61')`
  - Sync triggers: `chunks_ai` (AFTER INSERT), `chunks_ad` (AFTER DELETE), `chunks_au` (AFTER UPDATE) keeping FTS5 in sync with chunks table.
  - Return the Database instance.
- `indexDocument(db, { path, content, doc_type })`: Compute content hash (simple hash of content string). Check if document exists and hash matches -- skip if unchanged. Otherwise upsert document row, delete old chunks, chunk the content by paragraph (~200 token chunks -- split on double newlines, then combine short paragraphs), insert chunks, and FTS5 triggers handle the rest.
- `searchFTS5(db, query, limit=10)`: Escape FTS5 special characters from the query (`"'\()*+-:^{}~` replaced with spaces). Run the FTS5 MATCH query joining chunks_fts -> chunks -> documents, ORDER BY rank (BM25), LIMIT. Return array of `{ id, content, document_id, path, bm25_score }`.
- `reindexAll(db)`: Drop all chunks, re-scan watch paths from config.yaml, re-index all documents. Include `INSERT INTO chunks_fts(chunks_fts) VALUES('rebuild')` for FTS5 consistency.
- Use a simple content hash: `Buffer.from(content).toString('base64').slice(0, 32)` or similar. Don't import crypto if not needed.

**Step 2: Create `~/.openclaw/src/memory/vector-search.ts`** -- Qdrant vector search:

- Constants: COLLECTION_NAME = "openclaw-memory", EMBEDDING_DIM = 768, SIMILARITY_THRESHOLD loaded from config.
- Initialize Qdrant client: `new QdrantClient({ url: "http://127.0.0.1:6333" })`.
- Initialize Ollama client: `new Ollama({ host: "http://127.0.0.1:11434" })`.
- `initCollection()`: Check if collection exists via `getCollections()`. Create with `{ vectors: { size: 768, distance: "Cosine" } }` if not.
- `embed(text)`: Call `ollama.embed({ model: "nomic-embed-text", input: text })`. Return `response.embeddings[0]`. Handle errors -- if Ollama is unreachable, throw with clear message.
- `searchVector(query, limit=10, threshold=config.search.similarity_threshold)`: Embed the query, then `qdrant.search(COLLECTION_NAME, { vector: queryEmbedding, limit, score_threshold: threshold, with_payload: true })`. Return results with id, content (from payload.text), score.
- `upsertChunk(id, text, metadata)`: Embed the text, then `qdrant.upsert(COLLECTION_NAME, { points: [{ id, vector: embedding, payload: { text, ...metadata } }] })`.
- `deleteByPath(path)`: Delete all points where payload.path matches. Use scroll + delete pattern or filter delete.
- Use deterministic IDs: hash document path + chunk index into a numeric ID. Use a simple hash function that produces a positive integer within safe range. Record the mapping in the metadata payload (include path and chunk_index in payload).

**Step 3: Create `~/.openclaw/src/memory/hybrid-search.ts`** -- RRF merge with query-adaptive weights:

- `classifyQuery(query)`: Returns QueryType ("exact", "conceptual", "mixed").
  - "exact": query contains quoted strings, uppercase ID patterns (`[A-Z]{2,}[-_]\d+`), or looks like a specific name/term.
  - "conceptual": query contains how/why/what/strategy/decision/approach/pattern keywords.
  - "mixed": default.
- `getWeights(queryType)`: Returns `{ vector, fts5 }` weights per query type.
  - exact: `{ vector: 0.3, fts5: 0.7 }`
  - conceptual: `{ vector: 0.7, fts5: 0.3 }`
  - mixed: `{ vector: 0.6, fts5: 0.4 }` (default from config)
- `reciprocalRankFusion(vectorResults, fts5Results, weights, k=60)`: Merge results using RRF formula: `score = weight * (1 / (k + rank + 1))`. Use a Map to accumulate scores by chunk ID. Return merged results sorted by RRF score descending.
- `hybridSearch(query, limit=3)`:
  1. Classify the query type.
  2. Get adaptive weights.
  3. Run FTS5 search and Qdrant search in parallel (Promise.all).
  4. Normalize result formats to common shape.
  5. Apply RRF fusion.
  6. Return top `limit` results (default 3 per user decision). Each result includes `{ id, content, path, score, sources }` where sources indicates which backends contributed.
  7. If no results found, return empty array (caller should note "I don't have prior context on X" per user decision).
  8. Log the search: query type classification, weight split, result count, top score -- structured JSON to stderr.

**Step 1: Create `~/.openclaw/src/memory/compaction.ts`** -- Log compaction with tiered lifecycle:

- `scheduleCompaction()`: Use `node-cron` with the schedule from config.yaml (`"0 3 * * 0"` -- Sunday 3 AM). On trigger, run `runCompaction()`. Return the cron task handle for stopping.
- `runCompaction()`: Run both `compactDailyToWeekly()` and `compactWeeklyToMonthly()` in sequence. Log results as a structured JSON entry (component: "compaction").
- `compactDailyToWeekly(dryRun=false)`:
  1. Scan `~/.openclaw/memory/logs/` for daily log files older than 30 days (config: `retention_days`).
  2. Group by ISO week (Monday-Sunday).
  3. For each week with daily logs to compact: read all daily logs for that week, concatenate content.
  4. Generate a weekly summary: "Week of {start} - {end}: {summary of outcomes, decisions, notable events}". The summary should preserve the "arc" of activity per user's specific idea -- not just isolated facts but the narrative thread. Use a concise format: section headers for each day that had activity, bullet points for outcomes.
  5. Write summary to `~/.openclaw/memory/logs/summaries/{YYYY}-W{NN}.md`.
  6. If `dryRun` is false, delete the original daily files that were compacted.
  7. Return `CompactionResult` with stats.
- `compactWeeklyToMonthly()`:
  1. Scan `~/.openclaw/memory/logs/summaries/` for weekly summaries older than 90 days.
  2. Group by month.
  3. For each month: read all weekly summaries, concatenate.
  4. Generate a monthly summary at `~/.openclaw/memory/logs/summaries/{YYYY}-M{MM}.md`.
  5. Delete compacted weekly files.
  6. Monthly summaries persist indefinitely.
- For summary generation: Use a template-based approach (no LLM call needed for compaction -- just concatenate daily entries under week headers, preserving key lines). This avoids an LLM dependency in the compaction path. If LLM summarization is desired later, it can be added as an enhancement when the model router (Plan 02-02) is available.

**NOTE on compaction approach:** The user decision says "weekly compaction preserves outcomes plus notable context." For the initial implementation, use a structural compaction approach:
- Keep all lines containing "decision", "error", "client", "[interaction]" tags.
- Keep the first and last entry of each day (bookend context).
- Drop routine "[action]" entries that are purely internal operations.
- This produces concise but faithful weekly summaries without requiring an LLM.
