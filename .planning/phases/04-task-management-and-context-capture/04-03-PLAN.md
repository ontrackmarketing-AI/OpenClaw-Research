<objective>
Build the proactive check-in engine with adaptive timing and anti-repetition.

Purpose: The operator needs the agent to proactively surface priorities, status updates, and actionable items throughout the day -- not just react when asked. Without this, the todo list sits unread and context from iMessage, email, and meetings goes unsurfaced. The check-in engine transforms a passive database into an active assistant.

Output: A check-in engine with 5 daily time slots, context assembly from all sources (todos, calendar, iMessage, approvals, memory), LLM-personalized messages using anti-repetition template pools, SQLite-backed engagement tracking that adapts timing over 14 days, and inline Telegram buttons for operator responses.
</objective>

  6. Return selected TemplateEntry.

- Module-scope state: `_db: Database`, `_cronJobs: Map<string, ScheduledTask>`, `_lastCheckinIds: Map<string, number>` (maps checkin message to DB row ID for response tracking).

- `CHECKIN_PERSONALIZE_PROMPT` constant -- instructs the LLM to take a template skeleton and context (todos, calendar, messages, approvals) and produce a personalized, conversational check-in message. Rules: keep under 300 words, use the template as a starting structure but make it natural, include relevant numbers (e.g., "3 open todos"), mention specific items by name, end with a question if appropriate.

- `startCheckinEngine(bot: Bot, operatorChatId: number): void`:
  1. Initialize `_db` via `initCheckinDB()`.
  2. Call `getActiveSlots(_db)` to get current active slots.
  3. For each active slot, schedule a cron job at `SLOT_SCHEDULE[slot]`:
     - The cron callback calls `executeCheckin(slot, bot, operatorChatId)`.
  4. Store cron jobs in `_cronJobs` map.
  5. Log "checkin-engine started" with active slots list.
  6. Schedule a daily recalculation at midnight: re-evaluate getActiveSlots and reschedule cron jobs (slot adaptation).

- `stopCheckinEngine(): void` -- stops all cron jobs, clears `_cronJobs`.

- `executeCheckin(slot: CheckinSlot, bot: Bot, operatorChatId: number): Promise<void>`:
  1. Check `isOperatorBusy()`. If busy, log deferral, schedule retry in 15 minutes (setTimeout), return. Per research Pitfall 4: "When in doubt, stay quiet."
  2. Select template: `selectTemplate(slot, _db)`.
  3. Assemble context: `assembleCheckinContext(slot)`.
  4. Personalize via LLM: call `routeAndCall('checkin-personalize', [{role: 'user', content: CHECKIN_PERSONALIZE_PROMPT + JSON.stringify({template: template.template, context})}], '', 'checkin-engine')`.
  5. Strip code fences if any from response.
  6. Build inline keyboard with 3 buttons: `Got it` (`checkin:ack:{rowId}`), `Snooze 1hr` (`checkin:snooze:{rowId}`), `+ Todo` (`checkin:todo:{rowId}`).
  7. Send via `sendMessage(bot, operatorChatId, escapeMarkdownV2(personalizedText), { priority: 'normal', parseMode: 'MarkdownV2', replyMarkup: keyboard })`.
  8. Record in DB: `recordCheckin(_db, slot, template.id)`.
  9. Store the DB row ID in `_lastCheckinIds` map keyed by the Telegram message ID (if sendMessage returns it, or use a UUID).

- `triggerCheckin(slot?: CheckinSlot, bot?: Bot, operatorChatId?: number): Promise<void>` -- for on-demand /checkin command. Uses 'afternoon' as default slot. Skips busy check (user explicitly asked). Runs full personalize-and-send flow.
