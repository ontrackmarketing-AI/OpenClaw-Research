<objective>
Integrate iMessage as a context source via BlueBubbles for todo enrichment and check-in awareness.

Purpose: The operator receives business-relevant iMessages throughout the day that contain implicit action items ("Can you send the invoice?", "Let's schedule a call"). Without this integration, these items are invisible to the agent and fall through the cracks. iMessage context also makes check-ins more relevant by knowing what conversations are active.

Output: A BlueBubbles REST client with an abstraction layer for backend swapping, a privacy-preserving message poller that only processes business contacts, a context extractor that produces topic summaries without persisting message content, and todo creation from actionable messages.
</objective>

Create `src/imessage/types.ts`:
- `iMessageConfig` interface: `{ url: string; password: string; businessContacts: string[]; pollIntervalMs?: number; }`
- `BBMessage` interface: matching BlueBubbles REST API response shape:
  ```typescript
  {
    guid: string;
    text: string;
    dateCreated: number;       // Unix timestamp ms
    isFromMe: boolean;
    handle?: { address: string; };
    chats?: Array<{ guid: string; displayName?: string; }>;
  }
  ```
- `MessageContext` interface:
  ```typescript
  {
    sender: string;            // Phone number or email
    senderName?: string;       // Resolved name if available
    topicSummary: string;      // 5-10 word LLM summary
    timestamp: Date;
    chatGuid?: string;
    isActionable: boolean;     // LLM determines if this needs follow-up
  }
  ```
- Export all types.

Create `src/imessage/client.ts`:
- Reads config from env: `BLUEBUBBLES_URL` (default: `http://localhost:1234`), `BLUEBUBBLES_PASSWORD`.
- `createClient(config?: Partial<iMessageConfig>): iMessageClient` -- returns an object with methods below. This is the abstraction layer -- if BlueBubbles is replaced by chat.db relay, only this file changes.
- `getNewMessages(sinceDate: Date): Promise<BBMessage[]>` -- calls `GET {url}/api/v1/message?password={password}&after={sinceDate.getTime()}&limit=50&sort=ASC`. Uses Node 22 native `fetch`. Returns `data.data || []`.
- `getConversations(limit?: number): Promise<any[]>` -- calls `GET {url}/api/v1/chat?password={password}&limit={limit || 10}`. For future use.
- All fetch calls have a 5-second timeout via AbortController.
- If BLUEBUBBLES_PASSWORD is not set, all methods log warning and return empty arrays (graceful degradation).
- Log to stderr with `component: 'imessage-client'`.

Create `src/imessage/context.ts`:
- Import `routeAndCall` from `../router/router.js`.
- Import `createTodo` from `../todo/aggregator.js`.
- Parse `BUSINESS_CONTACTS` env var: `process.env.BUSINESS_CONTACTS?.split(',').map(c => c.trim()) || []`.
- `extractMessageContext(messages: BBMessage[], businessContacts: string[]): Promise<MessageContext[]>`:
  1. Filter to messages where `!isFromMe` AND `handle?.address` is in businessContacts.
  2. For each filtered message, call `routeAndCall('imessage-context', [{role: 'user', content: TOPIC_PROMPT + msg.text}], '', 'imessage-ctx')` with a prompt that asks for a JSON response: `{ "topic": "5-10 word summary", "actionable": true/false }`.
  3. Strip code fences, parse JSON.
  4. Build MessageContext with sender, topicSummary, timestamp, isActionable.
  5. **CRITICAL PRIVACY:** Do NOT store or return `msg.text` in any output. Only the topic summary and metadata are persisted.
  6. If isActionable is true, call `createTodo({ title: topicSummary, priority: 'medium', source: 'imessage', context: \`iMessage from ${msg.handle?.address}\`, sourceId: \`imessage:${msg.guid}\` })`.
  7. Return array of MessageContext objects.

- `getRecentBusinessContext(windowMinutes?: number): MessageContext[]` -- returns the in-memory cache of recent message contexts (kept in module-scope array, max 50 entries, last N minutes). This is what the check-in engine queries for iMessage context WITHOUT accessing message text.
- TOPIC_PROMPT: `"Summarize the topic of this message in 5-10 words. Also determine if it requires follow-up action. Return JSON: { \"topic\": \"...\", \"actionable\": true/false }. Do NOT include the original message text.\n\nMessage: "`
- Log to stderr with `component: 'imessage-context'`.

Create `src/imessage/poller.ts`:
- Import node-cron (already installed).
- Import `createClient` from `./client.js`.
- Import `extractMessageContext`, `getRecentBusinessContext` from `./context.js`.
- State tracking: last poll timestamp stored in `~/.openclaw/data/imessage-state.json`.
- `getLastPollTime(statePath?: string): Date` -- reads from state file, returns 1 hour ago if missing.
- `saveLastPollTime(timestamp: Date, statePath?: string): void` -- writes to state file.
- `pollOnce(): Promise<number>` -- single poll cycle:
  1. Get lastPollTime.
  2. Call `getNewMessages(lastPollTime)`.
  3. Pass messages to `extractMessageContext()`.
  4. Save new lastPollTime.
  5. Return count of contexts extracted.
- `startImessagePoller(intervalMinutes?: number): void` -- schedules pollOnce via node-cron every N minutes (default: 15). Log schedule on start.
- `stopImessagePoller(): void` -- cancels the cron job.
- Export `getRecentBusinessContext` re-export from context.ts for convenience.
- Log to stderr with `component: 'imessage-poller'`.
