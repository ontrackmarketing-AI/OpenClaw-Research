<objective>
Build the centralized todo aggregation system and transcript processing pipeline.

Purpose: The operator needs a single source of truth for tasks -- populated automatically from email, meetings, and call transcripts. Without this, action items from Fellow meetings and Apple Notes call recordings fall through the cracks, and email-derived tasks exist only in triage summaries that scroll away.

Output: A Notion todo database with CRUD operations, a central aggregator that deduplicates items by sourceId, an LLM-powered transcript extraction pipeline shared between Fellow and Apple Notes, and email-to-todo wiring from the existing poller.
</objective>

Create `src/todo/notion-todo.ts`:
- Import `createNotionClient`, `getDataSourceId` from `../notion/client.js`.
- `createNotionTodo(item: TodoItem, client?: Client, dbId?: string): Promise<void>` -- creates a Notion page in the todo database with properties:
  - `Task` (title): item.title
  - `Priority` (select): item.priority
  - `Source` (select): item.source
  - `Status` (select): item.status || 'open'
  - `Due Date` (date): item.dueDate ? { start: item.dueDate.toISOString() } : null
  - `Context` (rich_text): item.context || ''
  - `Source ID` (rich_text): item.sourceId || ''
  Uses `getDataSourceId()` for the data_source_id parent (per Phase 3 pattern). Database ID from `process.env.NOTION_TODO_DB_ID`.

- `todoExists(sourceId: string, client?: Client, dbId?: string): Promise<boolean>` -- queries the Notion database for any page where `Source ID` rich_text equals the given sourceId. Returns true if found. Uses `notion.databases.query()` with filter: `{ property: 'Source ID', rich_text: { equals: sourceId } }`. This is the dedup check (per research Pitfall 5).

- `queryTodos(query: TodoQuery, client?: Client, dbId?: string): Promise<TodoItem[]>` -- queries the Notion database with optional filters for status, source, and limit. Returns TodoItem[] parsed from Notion page properties. Used by the check-in engine (Plan 04-03) to get open todos for context assembly.

- Follow fire-and-forget error handling pattern from action-log.ts for createNotionTodo. If Notion API fails, log error to stderr but do NOT throw.
- Log to stderr with `component: 'notion-todo'`.

Create `src/transcripts/types.ts`:
- `ActionItem` interface: `{ task: string; assignee: string | null; due: string | null; }`
- `Decision` interface: `{ decision: string; context: string; }`
- `OpenQuestion` interface: `{ question: string; context: string; }`
- `ExtractedContent` interface:
  ```typescript
  {
    decisions: Decision[];
    actionItems: ActionItem[];
    openQuestions: OpenQuestion[];
    source: string;
    extractedAt: Date;
  }
  ```
- `TranscriptSource` type: `'fellow' | 'apple-notes'`
- `AppleNote` interface: `{ id: string; name: string; modificationDate: string; content: string; }`

Create `src/transcripts/extractor.ts`:
- Import `routeAndCall` from `../router/router.js` and `ChatMessage` from `../router/router.js`.
- Define `EXTRACTION_PROMPT` constant (per research Pattern 2) -- instructs the LLM to return JSON with decisions, action_items, and open_questions. Include rules about extracting implicit action items, using ISO dates, and assigning "operator" as default assignee.
- `extractFromTranscript(text: string, source: string, sessionId?: string): Promise<ExtractedContent>`:
  1. If text length exceeds 8000 tokens (~32000 chars), chunk into ~15-minute segments (~8000 chars each) and extract from each chunk separately, then merge results.
  2. Call `routeAndCall('transcript-extraction', [{role: 'user', content: EXTRACTION_PROMPT + text}], '', sessionId || 'transcript-extract', config)`.
  3. Strip markdown code fences from response (per Phase 3 pattern: `content.replace(/^```(?:json)?\s*\n?/, '').replace(/\n?```\s*$/, '')`).
  4. Parse JSON. Validate that at least one field (decisions, action_items, or open_questions) is populated. If empty, log warning.
  5. Return `ExtractedContent` with the parsed data, source, and extractedAt timestamp.
- `mergeExtractedContent(chunks: ExtractedContent[]): ExtractedContent` -- combines arrays from multiple chunks, deduplicates by task text.
- Log to stderr with `component: 'transcript-extractor'`.

Create `src/transcripts/fellow.ts`:
- Uses the Fellow Developer REST API (NOT MCP) since we need programmatic scheduled access.
- `FELLOW_API_BASE = 'https://api.fellow.ai/v1'` and reads API key from `process.env.FELLOW_API_KEY`.
- `getLastFellowCheckTime(statePath?: string): Date` -- reads last check timestamp from `~/.openclaw/data/fellow-state.json`. Returns epoch if file missing.
- `saveLastFellowCheckTime(timestamp: Date, statePath?: string): void` -- writes timestamp to state file.
- `fetchRecentMeetings(since: Date): Promise<FellowMeeting[]>` -- calls `GET /recordings?after={since.toISOString()}` with Bearer token auth. Returns list of meeting objects with id, title, date.
- `fetchMeetingTranscript(meetingId: string): Promise<string>` -- calls `GET /recordings/{meetingId}/transcript` with Bearer token. Returns transcript text.
- `processNewMeetings(): Promise<number>` -- the main orchestrator:
  1. Get lastCheckTime.
  2. Fetch recent meetings.
  3. For each meeting: fetch transcript, run extractFromTranscript(), create todos via createTodo() for each action item (with sourceId `fellow:{meetingId}:action:{index}`), also create todos for decisions (sourceId `fellow:{meetingId}:decision:{index}`) with priority 'low'.
  4. Save new lastCheckTime.
  5. Return count of todos created.
- If `FELLOW_API_KEY` is not set, log warning and return 0 (graceful degradation).
- Log to stderr with `component: 'fellow-transcripts'`.

Create `src/transcripts/apple-notes.ts`:
- Uses AppleScript via `child_process.execFile('osascript', ...)` (per research Pattern: Apple Notes Access).
- `getRecentNotes(limit?: number): Promise<AppleNote[]>` -- runs AppleScript to get the N most recent notes from Notes.app. Parses the AppleScript output (which returns delimited strings) into AppleNote objects. Timeout: 10 seconds.
- `searchNotes(keyword: string): Promise<AppleNote[]>` -- runs AppleScript to search for notes containing keyword. Timeout: 30 seconds. Escapes double quotes in keyword.
- `processCallTranscripts(keyword?: string): Promise<number>` -- the main orchestrator:
  1. Search for notes matching keyword (default: 'call transcript' or 'Plaud' or 'recording').
  2. For each matching note: run extractFromTranscript() with the note content.
  3. Create todos via createTodo() for each action item (sourceId `apple-notes:{noteId}:action:{index}`).
  4. Return count of todos created.
- If AppleScript fails (permissions not granted), log error and return 0 (graceful degradation).
- Log to stderr with `component: 'apple-notes-transcripts'`.
