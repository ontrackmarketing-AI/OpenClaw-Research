  <name>Task 1: Create hardened Docker Compose stack with all services</name>
  <files>~/.openclaw/docker-compose.yml, ~/.openclaw/.env, ~/.openclaw/data/</files>
  <action>
Create the complete Docker Compose stack at `~/.openclaw/docker-compose.yml` with all 5 services on the `openclaw-net` bridge network.

**Pre-flight:**
1. Create data directories: `mkdir -p ~/.openclaw/data/{postgres,redis,qdrant,n8n}`
2. Determine correct UIDs: Run `docker run --rm postgres:16-alpine id` and `docker run --rm redis:7-alpine id` to get actual container UIDs. Use those UIDs in the `user:` directive AND `chown` the corresponding data directories to match.
3. Generate secrets for `.env`:
   - `POSTGRES_PASSWORD`: Generate random 32-char alphanumeric
   - `REDIS_PASSWORD`: Generate random 32-char alphanumeric
   - `N8N_AUTH_USER`: Set to `admin`
   - `N8N_AUTH_PASSWORD`: Generate random 32-char alphanumeric
   - `N8N_ENCRYPTION_KEY`: Generate random 64-char hex string
4. Write `~/.openclaw/.env` with `chmod 600`

**Docker Compose services (all on `openclaw-net` bridge):**

**postgres** (`postgres:16-alpine`):
- Container name: `openclaw-postgres`
- User: UID from pre-flight step (likely 70 for Alpine)
- Ports: `127.0.0.1:5432:5432` (INFR-03: localhost only)
- Volumes: `~/.openclaw/data/postgres:/var/lib/postgresql/data`
- Environment: `POSTGRES_USER=openclaw`, `POSTGRES_PASSWORD=${POSTGRES_PASSWORD}`, `POSTGRES_DB=openclaw`
- Hardening (INFR-02): `read_only: true`, `security_opt: [no-new-privileges:true]`, `cap_drop: [ALL]`, `pids_limit: 100`
- tmpfs: `/tmp:size=64M,noexec,nosuid,nodev` AND `/run/postgresql:size=16M` (postgres needs this for socket file)
- Resources: memory 2G, cpus 1.0
- Healthcheck: `pg_isready -U openclaw` every 30s
- Logging: json-file, max-size 10m, max-file 3
- restart: unless-stopped

**redis** (`redis:7-alpine`):
- Container name: `openclaw-redis`
- User: UID from pre-flight step (likely 999 for redis-alpine)
- Ports: `127.0.0.1:6379:6379`
- Volumes: `~/.openclaw/data/redis:/data`
- Command: `redis-server --requirepass ${REDIS_PASSWORD} --save 60 1000 --loglevel warning --maxmemory 512mb --maxmemory-policy allkeys-lru`
- Hardening: same as postgres (read_only, no-new-privileges, cap_drop ALL, pids_limit 50)
- tmpfs: `/tmp:size=32M,noexec,nosuid,nodev`
- Resources: memory 1G, cpus 0.5
- Healthcheck: `redis-cli -a ${REDIS_PASSWORD} ping` every 30s
- Logging: json-file, max-size 10m, max-file 3

**qdrant** (`qdrant/qdrant:latest`):
- Container name: `openclaw-qdrant`
- Ports: `127.0.0.1:6333:6333`, `127.0.0.1:6334:6334`
- Volumes: `~/.openclaw/data/qdrant:/qdrant/storage`
- Hardening: `read_only: true`, `security_opt: [no-new-privileges:true]`, `cap_drop: [ALL]`, `pids_limit: 100`
- tmpfs: `/tmp:size=64M,noexec,nosuid,nodev`
- Resources: memory 2G, cpus 1.0
- Healthcheck: `curl -f http://localhost:6333/healthz` every 30s
- Note: Do NOT set `user:` for Qdrant -- the official image handles its own user. Test if it works without; if permission errors occur on the bind mount, chown the qdrant data dir to the container's UID.

**n8n** (`n8nio/n8n:2.5.2` -- PINNED for CVE-2026-25049):
- Container name: `openclaw-n8n`
- User: `1000:1000`
- Ports: `127.0.0.1:5678:5678`
- Volumes: `~/.openclaw/data/n8n:/home/node/.n8n`
- Environment: `N8N_BASIC_AUTH_ACTIVE=true`, `N8N_BASIC_AUTH_USER=${N8N_AUTH_USER}`, `N8N_BASIC_AUTH_PASSWORD=${N8N_AUTH_PASSWORD}`, `N8N_PORT=5678`, `N8N_PROTOCOL=http`, `N8N_HOST=0.0.0.0`, `WEBHOOK_URL=http://localhost:5678/`, `N8N_ENCRYPTION_KEY=${N8N_ENCRYPTION_KEY}`, `GENERIC_TIMEZONE=America/Chicago`
- Hardening: `security_opt: [no-new-privileges:true]`, `cap_drop: [ALL]`, `pids_limit: 150`
- Note on read_only: Test with `read_only: true` first. If n8n fails to start, remove `read_only` and add targeted tmpfs mounts for any additional writable paths identified via `docker diff openclaw-n8n`. Log which paths needed writable access.
- Resources: memory 2G, cpus 1.5
- Healthcheck: `curl -f http://localhost:5678/healthz` every 30s, timeout 10s
- depends_on: postgres (n8n can use postgres as backend)

**All services:**
- `restart: unless-stopped`
- Logging driver: `json-file` with `max-size: "10m"` and `max-file: "3"`
- Network: `openclaw-net` (bridge)

**After writing docker-compose.yml:**
- Run `docker compose -f ~/.openclaw/docker-compose.yml config` to validate syntax
- Run `docker compose -f ~/.openclaw/docker-compose.yml up -d`
- Wait for all containers to report healthy: `docker compose -f ~/.openclaw/docker-compose.yml ps`
- If any container fails, check logs (`docker logs <container>`), fix, and retry

**Ollama models (INFR-04):**
1. Verify Ollama is running: `curl -s http://localhost:11434/api/tags`
2. Pull required models:
   - `ollama pull qwen3:14b` (primary local LLM)
   - `ollama pull nomic-embed-text` (embeddings for RAG)
3. Verify models respond:
   - `curl -s http://localhost:11434/api/generate -d '{"model":"qwen3:14b","prompt":"Hello","stream":false}' | head -c 200`
   - `curl -s http://localhost:11434/api/embed -d '{"model":"nomic-embed-text","input":"test embedding"}' | head -c 200`
4. Verify Docker containers can reach Ollama on host:
   - `docker exec openclaw-n8n curl -s http://host.docker.internal:11434/api/tags`
   - If connection refused: Check Ollama is listening on `0.0.0.0:11434` (not just 127.0.0.1). If needed, set `OLLAMA_HOST=0.0.0.0` in Ollama's environment and restart.

**Tailscale serve (INFR-05):**
1. Verify Tailscale is connected: `tailscale status`
2. Configure Tailscale serve for each port:
   - `tailscale serve --bg 3000` (Dashboard)
   - `tailscale serve --bg --set-path /n8n 5678` OR `tailscale serve --bg 5678` (n8n -- use separate port if path-based serving is not ideal, check tailscale serve docs for multi-port)
   - Note: `tailscale serve` on multiple ports may require running as separate `tailscale serve` commands with `--https` flag for different ports. Check `tailscale serve --help` for the current syntax. If multiple ports on separate subdomains are not supported, use `tailscale serve` for the primary port (3000) and document manual SSH tunnel as fallback for n8n.
3. Verify from host: `curl -s https://brysons-mac-mini.tail<TAILNET>.ts.net/` (should reach dashboard)
4. ACL configuration is a user_setup item -- document what the operator must configure in the Tailscale admin console (restrict to ports 3000, 18789, 5678, 22 for autogroup:owner only).
