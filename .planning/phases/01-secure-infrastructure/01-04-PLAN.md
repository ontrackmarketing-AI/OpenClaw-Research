**Gap 1 Fix: Qdrant non-root (INFR-02)**

1. Stop the Qdrant container:
   ```bash
   docker compose -f ~/.openclaw/docker-compose.yml stop qdrant
   ```

2. Chown the Qdrant data directory to UID 1000:1000 so the non-root container can write to it:
   ```bash
   sudo chown -R 1000:1000 /Users/b2/.openclaw/data/qdrant
   ```
   Note: On macOS, `sudo chown` works for setting arbitrary UIDs even though UID 1000 does not exist as a local user. If `sudo` is not available or fails, try `chown -R 1000:1000` without sudo (macOS admin user can sometimes chown to numeric UIDs). If permission issues persist, the executor should check if Docker Desktop handles UID mapping transparently (some Docker Desktop versions on Mac use a Linux VM where file ownership is virtualized).

3. Edit `~/.openclaw/docker-compose.yml` -- add `user: "1000:1000"` to the qdrant service block. Insert it directly after the `restart: unless-stopped` line (consistent with n8n service placement). The resulting qdrant service should look like:
   ```yaml
     qdrant:
       image: qdrant/qdrant:latest
       container_name: openclaw-qdrant
       restart: unless-stopped
       user: "1000:1000"
       read_only: true
       security_opt:
         - no-new-privileges:true
       cap_drop:
         - ALL
       # ... rest unchanged ...
   ```

4. Start the Qdrant container:
   ```bash
   docker compose -f ~/.openclaw/docker-compose.yml up -d qdrant
   ```

5. Wait for the healthcheck to pass:
   ```bash
   docker compose -f ~/.openclaw/docker-compose.yml ps qdrant
   ```
   If the container fails to start or the healthcheck fails:
   - Check logs: `docker logs openclaw-qdrant`
   - Common issue: Qdrant may need to write to paths other than `/qdrant/storage`. If so, check `docker logs` for the specific path and add a targeted tmpfs mount for it.
   - If the issue is the snapshots tmpfs: the existing `tmpfs: /qdrant/snapshots:size=256M` should cover that writable path.

6. Verify non-root:
   ```bash
   docker inspect openclaw-qdrant --format '{{.Config.User}}'
   # Expected: "1000:1000"

   docker exec openclaw-qdrant id
   # Expected: uid=1000 (not uid=0)
   ```

7. Verify Qdrant is functional:
   ```bash
   docker exec openclaw-qdrant bash -c 'exec 3<>/dev/tcp/localhost/6333 && echo -e "GET /healthz HTTP/1.1\r\nHost: localhost\r\n\r\n" >&3 && timeout 2 cat <&3'
   # Expected: HTTP 200 OK
   ```
