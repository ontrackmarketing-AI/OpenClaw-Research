**Type definitions (`~/.openclaw/src/hitl/types.ts`):**

```typescript
export type Tier = 'RED' | 'YELLOW' | 'GREEN';

export interface ActionRequest {
  action: string;
  params: Record<string, unknown>;
  source: string;
  timestamp: Date;
}

export interface HITLResult {
  allowed: boolean;
  tier: Tier;
  reason: string;
  logged: boolean;
}

export interface TierConfig {
  tiers: Record<Tier, string[]>;
}
```

**Classification module (`~/.openclaw/src/hitl/classify.ts`):**

Implement `classifyAction(action: string, tiers: TierConfig): Tier`:
1. **HARDCODED RULE (SECR-07):** If `action.toLowerCase().includes('delete')`, return `'RED'` immediately. This check MUST come first and CANNOT be overridden by the YAML config.
2. Check config-based tiers in order: RED, YELLOW, GREEN.
3. Support wildcard patterns (e.g., `read_*` matches `read_contacts`, `read_emails`).
4. **Default unknown actions to RED** (fail-secure).

**Enforcement module (`~/.openclaw/src/hitl/enforce.ts`):**

Implement `enforceHITL(request: ActionRequest, config: TierConfig): HITLResult`:

Include a `loadTierConfig(configPath: string): TierConfig` function that reads and parses the YAML file. Use `yaml` npm package for parsing (add to package.json if needed).

**IMPORTANT:** n8n workflows are created through the n8n UI/API, not as code files. Use the n8n REST API to create workflows programmatically.

**Pre-flight:**
1. Get n8n credentials: Read N8N_AUTH_USER and N8N_AUTH_PASSWORD from `~/.openclaw/.env`
2. Verify n8n is running: `curl -u $N8N_AUTH_USER:$N8N_AUTH_PASSWORD http://localhost:5678/api/v1/workflows`

**Step 1: Create the shared sanitizer sub-workflow**

Use the n8n API to create a workflow named "Sanitizer" that:
- Input: Receives payload from calling workflow via "Execute Sub-Workflow" trigger
- Processing (Function node with JavaScript):
  1. Strip prompt injection patterns: `ignore previous instructions`, `you are now`, `system:`, `[INST]`, `<<SYS>>`, `<|im_start|>`, base64 decode commands, curl pipe bash patterns
  2. Strip invisible Unicode characters (zero-width spaces, directional overrides: U+200B-U+200F, U+2028-U+202F, U+2060-U+206F, U+FEFF)
  3. Strip hidden HTML/CSS (`display:none`, `font-size:0`, `<style>` blocks)
  4. Truncate payloads > 50KB
  5. Return `{ sanitized: <cleaned payload>, flags: [<detected issues>], was_modified: boolean }`
- The sanitizer code should match the pseudocode in 01-RESEARCH.md

**Step 2: Create 6 proxy workflows**

Each proxy workflow follows the same pattern:
1. **Webhook Trigger** node: POST endpoint at `/webhook/proxy-{service-name}`
2. **Execute Sub-Workflow** node: Call the Sanitizer sub-workflow with the request payload
3. **HTTP Request** node: Call the external API using credentials from n8n's credential store
4. **Respond to Webhook** node: Return the API response to the agent

The 6 proxy workflows:
1. `proxy-clay` -- Clay enrichment API (`/webhook/proxy-clay`)
2. `proxy-ghl-contacts` -- GoHighLevel contacts API (`/webhook/proxy-ghl-contacts`)
3. `proxy-ghl-messages` -- GoHighLevel messages API (`/webhook/proxy-ghl-messages`)
4. `proxy-email` -- Email sending API (SendGrid/Mailgun) (`/webhook/proxy-email`)
5. `proxy-dataforseo` -- DataForSEO API (`/webhook/proxy-dataforseo`)
6. `proxy-serper` -- Serper search API (`/webhook/proxy-serper`)

**Per user decision:** Proxy workflows for services with available API keys should be fully configured. Services without keys get stub workflows that return `{ "status": "stub", "message": "API key not configured", "service": "<name>" }` so the agent handles gracefully. Since this is Phase 1 and we may not have all API keys, implement ALL 6 as stub workflows first, with clear TODO comments marking where to add the actual HTTP Request node with credentials.

**Step 3: Activate all workflows**

Use the n8n API to activate all 7 workflows (1 sanitizer + 6 proxies). Production webhooks only activate when the workflow is active.
